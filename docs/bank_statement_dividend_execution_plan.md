# 银行流水股息提取改造任务执行方案

## 1. 目标

本次改造的目标不是一次性推翻现有解析链路，而是在现有 `文件解析 -> AI 抽取 -> 后处理 -> 导出` 流程上，逐步补齐以下能力：

1. 将不同来源的材料统一成可复用的交易流水中间表示。
2. 将“识别、抽取、规范化”拆成清晰的执行阶段，降低单一 Prompt 的复杂度。
3. 为后续的自动路由、股息专用抽取、人工复核和持续优化提供基础数据。

## 2. 执行原则

1. 先做基础层，再做业务层。
2. 先保证兼容，再逐步替换旧链路。
3. 每一阶段都要有可观测产物，避免一次性大改。
4. 优先沉淀可以复用的通用能力，不先写大量特化 Prompt。

## 3. 阶段划分

### 阶段一：统一中间表示与解析基础层

#### 本阶段完成什么

把 PDF、Excel 两类输入先统一成交易流水 IR 和文档特征摘要，为后续路由和股息专用抽取打地基。

#### 需要做的内容

1. 设计统一交易流水对象
   - 定义交易流水最小字段集
   - 明确证据链、原始行数据、来源信息的承载方式
2. 建立 PDF -> 交易流水 IR 的转换能力
   - 将表格结构转为表头 + 行数据
   - 补充页码、表格标题、行号等追溯信息
3. 建立 Excel -> 交易流水 IR 的转换能力
   - 保留表头原始列名
   - 补充行号、sheet 信息等上下文
4. 建立文档特征提取能力
   - 提取文件类型、表头、关键字段特征
   - 提取是否存在余额列、借贷拆分、日期列、金额列等指标
5. 将 IR 与特征提取接入现有解析入口
   - 在不改变现有 AI 输出协议的前提下挂到 PDF / Excel 解析流程
   - 让后续步骤可以直接消费这些中间结果

#### 本阶段产物

1. 统一交易流水 IR
2. 文档特征摘要结构
3. PDF / Excel 解析预处理能力
4. 现有解析链路中的基础挂载点

#### 完成标准

1. PDF / Excel 输入都能产出统一的交易流水列表
2. 每条流水都能追溯到原始来源
3. 不影响现有 AI 抽取与导出流程

### 阶段二：配置模型扩展与路由准备

#### 本阶段完成什么

让系统从“外部直接指定文档模板”过渡到“系统可先识别材料类型，再选择模板或抽取器”。

#### 需要做的内容

1. 扩展文档配置模型
   - 支持匹配规则、变体标识、差异化 Prompt 补丁
2. 扩展任务项元数据
   - 支持保存识别结果、置信度、原因、是否需要人工复核
3. 明确分类维度
   - 区分银行流水、股息汇总、券商报表、用户自制表等类型
4. 明确“用户手选”和“系统自动识别”的兼容策略

#### 本阶段产物

1. 路由配置模型
2. 任务项识别结果模型
3. 路由前置约束与兼容方案

#### 完成标准

1. 系统可以承载识别结果和复核标识
2. 后续路由逻辑有明确的落点，不再依赖硬编码

### 阶段三：文档路由能力

#### 本阶段完成什么

增加“规则优先、AI 兜底”的文档识别与路由能力。

#### 需要做的内容

1. 建立规则路由
   - 基于文件类型、表头、关键词、排除词做初筛
2. 建立候选类型集合
   - 将不可能的类型提前排除
3. 在规则不确定时加入 AI 分类兜底
   - 控制输入规模，只传特征与少量样本
4. 输出标准路由结果
   - 类型、变体、置信度、原因、复核标志
5. 将路由结果接入任务执行流程
   - 兼容现有 documentId 指定模式

#### 本阶段产物

1. 文档路由服务
2. 规则匹配能力
3. AI 兜底分类能力
4. 路由结果结构

#### 完成标准

1. 对常见材料能自动判断大类
2. 低置信结果不会误路由到错误模板
3. 手工指定模板仍然可用

### 阶段四：股息专用抽取链路

#### 本阶段完成什么

把当前“大 Prompt 直接抽取”改造成“候选流水召回 + 股息专用结构化抽取”。

#### 需要做的内容

1. 基于统一流水做候选召回
   - 先筛出可能与股息相关的流水
2. 建立股息统一输出结构
   - 支持净额、税额、毛额、币种、付款方、证据链等字段
3. 建立股息专用抽取逻辑
   - 先规则，后小范围 LLM 结构化
4. 将股息抽取结果接回现有任务结果结构
   - 保持 records / warnings / errorRecords 兼容

#### 本阶段产物

1. 股息候选召回能力
2. 股息统一 schema
3. 股息专用抽取器

#### 完成标准

1. 对银行流水中的股息类交易能进行专项提取
2. LLM 输入规模明显小于当前整表直喂模式

### 阶段五：规范化、质量评估与人工兜底

#### 本阶段完成什么

让系统不仅能抽取，还能判断结果是否可靠，并把低置信结果送入复核流程。

#### 需要做的内容

1. 增加规范化处理
   - 日期、币种、金额方向、税额语义统一
2. 增加质量校验
   - 缺失字段、金额方向冲突、余额异常、重复记录等
3. 增加置信度与告警信息
4. 输出复核所需证据链
5. 为后续前端复核页面保留必要字段

#### 本阶段产物

1. 规范化规则
2. 质量评估规则
3. 复核标记与证据链字段

#### 完成标准

1. 系统可识别高风险结果
2. 低置信结果可被人工快速定位和修正

## 4. 当前开发顺序

当前先按以下顺序推进：

1. 优先完成阶段一
2. 在阶段一稳定后进入阶段二和阶段三
3. 股息专用抽取放在路由之后落地
4. 质量评估在专项抽取稳定后接入

## 6. 阶段验收方式

### 阶段一验收

1. 输入 PDF 时，系统能识别表格并产出交易流水基础对象
2. 输入 Excel 时，系统能产出行级交易流水基础对象
3. 解析结果中能看到文档特征摘要
4. 现有任务创建、AI 抽取、导出链路不回归

### 后续阶段验收

后续每个阶段都按以下标准验收：

1. 有明确输入
2. 有明确输出
3. 有兼容策略
4. 有可观测结果

## 8. 当前可观测与验证入口

### 任务执行结果查询

1. 创建任务后，可通过 `/tasks/{taskId}` 查询任务状态与任务项详情。
2. 任务项中已可查看：
   - 路由后的 `resolved_document_id`
   - 路由置信度与原因
   - `need_human_review`
   - `review_reasons`
   - `change_result`
3. 当人工完成复核后，可通过 `/tasks/items/{itemId}/review` 回写：
   - 修正后的 `records`
   - 是否仍需人工复核
   - `review_reasons`
   - `reviewer`
   - `comment`
   - 修正后的 `resolvedDocumentId`
4. 每次人工复核回写后，系统会自动生成一条学习资产，可通过 `/review-learning` 查询：
   - 复核后的结构化记录
   - 复核备注与原因
   - 当前路由摘要
   - 建议补充的 `matchRule`
   - 可复用的 few-shot 示例

### 内置样本验证

1. 当前已提供 `/validation/dividend-samples` 校验入口。
2. 该入口会基于内置样本验证以下能力：
   - 文档路由结果是否符合预期
   - 股息候选召回数量
   - 股息专项输出数量
   - 是否正确触发人工复核标记
   - 重复股息记录是否进入人工复核
3. 当前样本存放位置：
   - `src/main/resources/validation/dividend-validation-samples.json`

### 持续学习资产

1. 持续学习入口用于沉淀“用户确认的类型 + 抽取结果修正”。
2. 当前沉淀内容包括：
   - 路由摘要
   - 复核后的 records
   - review 原因与备注
   - 建议补充的 matchRule 关键词
   - few-shot 示例结构
3. 当前查询入口：
   - `/review-learning`
   - 可选参数：`documentType`
4. 当前复核学习资产已开始反哺后续路由：
   - 规则路由会额外参考复核沉淀关键词
   - AI fallback 会带上少量 few-shot 示例和学习关键词
